## From database row to physical bin

Inventory software can identify an item instantly. A person still has to map that answer onto a physical shelf. This project closes that gap by actuating the selected location, reducing search time and making the digital state visible in the real environment.

That simple interaction spans a surprising number of domains: networked software, GPIO expansion, inductive-load drivers, power distribution, mechanical mounting, and fault recovery.

## System architecture

The controller should never drive a solenoid directly. A dedicated driver stage handles current, flyback energy, and channel isolation while the Raspberry Pi owns selection logic and system state.

> The interface is successful only if the correct bin actuates every time—and a software restart cannot leave a coil energized.

### Electrical design concerns

- Solenoid pull-in and hold current
- Simultaneous-channel power budget
- Flyback suppression and driver stress
- Logic-level compatibility
- Startup and shutdown output states
- Connector and harness serviceability

## Reliability tests

The most persuasive validation is a repeated selection test across every channel, including rapid commands and deliberate power interruption.

## What I would improve next

A mature revision would add explicit actuation feedback rather than assuming that electrical drive produced mechanical motion. Current sensing, a position switch, or another confirmation method would turn the system from command-driven to verifiably closed-loop.
